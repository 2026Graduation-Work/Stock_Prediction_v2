# 투자스타일 진단 심화와 HITL 표현 체계 도입 계획

> 기준일: 2026-07-28. 근거 자료: 외부 교육용 웹 애플리케이션 1종(읽기 전용 분석)과
> PB 포트폴리오 제안 발표자료 1종. 저장소 규칙에 따라 본 문서와 이후 산출물에서
> 외부 프로젝트명은 표기하지 않고 "참고 자료"로만 부른다.
>
> 이 문서는 제안이다. 확정된 규칙은 `AGENTS.md`에, 일정·DoD는 노션 "과제 안내서 v1.2"에 둔다.

---

## 1. 왜 지금 이 작업인가

참고 자료를 검토한 결과, 우리가 가져올 것은 화면 스킨이 아니라
**이미 `AGENTS.md`에 선언한 원칙의 금융 도메인 표현**이다.

| 우리 원칙 (AGENTS.md) | 참고 자료의 대응 표현 |
| --- | --- |
| 명시 규칙만 하드 제약, 성향 점수는 소프트 | 시장 전망은 **소프트 틸트**, 고객 조건은 **하드 제약** |
| HITL — 자동 매매·손절·익절 실행 금지 | 상담의 결론은 매수가 아니라 **기준·정책비중·재점검 규칙의 합의**. 재점검 신호는 **매도 지시가 아님** |
| 화이트박스 — 근거를 비전공자에게 설명 | 편입 근거를 **"필요성 / 기대 역할"** 2단으로 서술. 수익률 전망이 아니라 조건의 부족분 보완 |

세 번째 줄이 지금 가장 필요하다. PR #35·#38에서 사용자 노출 행동 제안 문구를 제거했지만,
**그 자리에 무엇을 놓을지는 정하지 않았다.** 참고 자료는 그 답을 갖고 있다 —
매매 지시 대신 **사전에 합의한 재점검 규칙**이다. 사용자가 직접 정한 명시 규칙이므로
우리 하드 제약 정의에 그대로 들어맞는다.

따라서 이 작업은 새 기능 추가가 아니라 **합의된 원칙을 사용자에게 보이는 언어로 완성하는 것**이다.

## 2. 목표

### G1. 진단 해상도 — 3축 5문항에서 8축 다문항으로

현재 `backend/profiling/survey/`는 객관식 5문항 + 자유 텍스트 1문항이고,
문항 하나가 축 하나에 대응하므로 **응답 일관성을 볼 수 없다.**
그래서 스키마의 `confidence_per_field`를 실제로 계산할 근거가 없다.

- 완료 판정: 축별 복수 문항 + 리커트 5점 + 문항 가중치로 점수를 내고,
  `confidence_per_field`가 응답 일관성에서 결정론적으로 산출된다.
- 불변: 점수 산출은 100% 결정론(같은 입력 → 같은 출력), LLM 미사용.

### G2. 행동재무학 관찰 — 축 간 모순 검출

행동재무학 기반 프로젝트인데 **모순 검출이 없다.**
현재 스키마에는 `free_text_signal.conflict_with_survey` 불리언 하나뿐이다.

참고 자료는 축 간 상충(예: 손실 회피가 강한데 고베타 집중을 선호)을 규칙으로 잡아
후속 확인 문항과 상담 톤을 함께 제시한다. **우리 연구 주제에 가장 직접적으로 기여하는 항목**이다.

- 완료 판정: 모순 규칙마다 단위 테스트가 있고, 검출 시 후속 확인 문항과 심각도를 출력한다.

### G3. HITL 표현의 빈자리 채우기

- 재점검 신호 임계를 **미리** 제시하고, "기준에 닿으면 멈추고 재점검", "매도 지시가 아님"을 명시
- 정책비중 상한(단일 종목·단일 테마)을 사용자와 사전 합의
- 정기 점검 주기를 명시
- 완료 판정: 대시보드·종목 상세에 재점검 신호 표현이 있고 기존 금지 표현 검사를 통과한다.

### G4. 데모 안정성 — 2모드 진단과 페르소나 프리셋

발표 중에 설문을 끝까지 풀 수 없다. 참고 자료는 정밀·빠른 2모드와 데모 프리셋을 둔다.

- 완료 판정: 프리셋 선택에서 결과 화면까지 E2E가 통과하고, 발표자가 문항을 풀지 않아도 된다.

### 하지 않을 것

- 포트폴리오 구성, 계좌 배분(ISA·연금·IRP), 세금 계산 — 우리는 개별 종목 예측 플랫폼이지
  포트폴리오 설계 제품이 아니다.
- 실시간 외부 시세·거시 지표 연동 — 참고 자료의 해당 모듈만 4,700줄로 범위 밖이다.
- 참고 자료 코드 이식 — 5절 참조.

## 3. 연구 경로에 대한 영향

없다. A/B 실험은 `synthetic_psychology_index`를 입력으로 쓴다(로드맵 P0 연구 경로).
설문 확장은 **제품 경로(DoD 2)** 만 개선하고 **연구 경로(DoD 1)** 의 입력을 바꾸지 않는다.
스코프가 늘어도 연구 일정이 밀리지 않는다.

## 4. 단계

### Phase 0 — 프론트엔드 체인 복구 (선행 조건)

로드맵 통합 현황 2번(`#29 → #30 → (#31, #33) → #34`)이 부모 브랜치에만 병합되어
약 2,300줄이 `main`에 도달하지 못했다. UI 작업의 선행 조건이므로 먼저 처리한다. → PR #41

### Phase 1 — 계약: schema v1.1 (additive)

`schema/`는 v1.0 freeze다. **기존 필드를 바꾸지 않고 추가만** 해서 chart·text 블록을 무영향으로 둔다.

- `style_axes` (optional) — 8축 점수와 축별 신뢰도
- `contradictions` (optional) — 검출된 모순 목록
- `assessment_mode` (optional) — `quick` | `detailed`
- 기존 `investor_profile` 3축은 8축에서 **결정론적으로 축약해 계속 채운다**(하위 호환)
- `[schema]` 제목 + 전원 멘션 PR

### Phase 2 — profiling 백엔드 (담당: 중현 🟡)

`backend/profiling/survey/` 확장. 순수 Python, 결정론, LLM 미사용.

1. 문항 은행 — 8축, 축당 복수 문항, 리커트 5점, 축별 방향과 가중치
2. 2모드 — 축당 문항 수만 다르고 스코어링은 동일
3. 스코어링 — 축 점수 대 최대점 비율, 축별 신뢰도(응답 일관성 기반)
4. 모순 검출 — 규칙 테이블, 후속 확인 문항, 심각도
5. 3축 축약 — 8축에서 기존 `risk_tolerance` · `time_horizon_months` · `fomo_index` 산출
6. 페르소나 프리셋 — 발표용 고정 응답셋

게이트: `ruff check .`, `pytest`. 모순 규칙마다 테스트 1개 이상.

### Phase 3 — 진단·결과 화면 (담당: 성우 🔵 + 중현 🟡)

Phase 0 병합 후 착수. 기존 `frontend/app/survey/survey-flow.tsx` 확장.

- 진행률과 남은 예상 시간, 영역 탭 이동, "정답은 없습니다 · 이전 답변 유지" 안내
- 결과 화면의 축별 5칸 강도 표시와 유형 코드
- 결과 카드 3분할 — **가장 중요하게 보는 것 / 잘 맞는 운영 방향 / 주의할 순간**
  (마지막 칸이 행동재무학 관찰을 놓을 자리)
- 접이식 상세 기준 — 일반 사용자에게는 감추고 심사·발표에서 펼침
- 면책 문구 고정 배치

게이트: `pnpm lint`, `pnpm build`, 1440px·1024px, 콘솔 오류 0.

### Phase 4 — 표현 체계 통일 (전원)

- `AGENTS.md`에 **하드 제약 / 소프트 틸트** 용어를 명문화(현재 개념만 있고 용어가 없다)
- 재점검 신호 표현을 `frontend/lib/display.ts` 문구 규칙에 반영
- 종목 상세 근거를 **필요성 / 기대 역할** 2단 서술로 정리
- 금지 표현 검사에 허용 표현 화이트리스트 추가(지금은 문구를 지우기만 한다)

### Phase 5 — 선택

참고 자료의 거시 소프트 틸트를 text 블록 `current_market_anxiety`와 연결.
연구 경로에 영향을 주므로 **A/B 실험 완료 후에만** 검토한다.

## 5. 준수 사항

1. **참고 자료 저장소에 LICENSE 파일이 없다.** 기본값은 저작권 유보이므로
   **코드를 복사하거나 이식하지 않는다.** 개념·구조·도메인 지식만 취하고 독립 구현한다.
2. `AGENTS.md`: 다른 팀·조직 레포는 읽기 전용으로 참고하고 분석 후 클론을 삭제한다.
3. `AGENTS.md`: 팀 산출물에 외부 프로젝트명을 명시하지 않는다.
4. 발표자료의 시장 수치(금리·GDP·순매수 등)는 특정 증권사 리서치 인용물이다.
   우리 산출물에 옮기려면 출처를 명시하거나 쓰지 않는다.
   **도입 대상은 수치가 아니라 설계 원칙이다.**
